Rotate Your First Logs

In one minute

You rotate and compress a log file with Driftwood 2.4.0 in a throwaway folder, so nothing outside that folder changes. You finish with a compressed Generation, a restored copy of it and a driftwood.toml you wrote yourself. You need a terminal and Driftwood 2.4.0 on your path. There are six steps, and each one ends with the output you should see. The page is sample content for a fictional product and was never run.

What you will do

The list gives each step an ID, so other tabs and the failure table can point to it.

  • S1. Create the Sandbox. Make a scratch folder holding a 2,000-line log file.
  • S2. Create the config. Run driftwood init to get a default driftwood.toml.
  • S3. Set the limits. Lower max_size to 64KB and keep to 3 so the log is large enough to rotate.
  • S4. Check before you run. Ask Driftwood what it would do, without changing a file.
  • S5. Run the Rotation. Move the Live log into a compressed Generation.
  • S6. Restore the Generation. Copy the Generation back, to see the run can be undone.

Do the steps

  1. Create the Sandbox with a sample log

    Step 1 of 6 · Changes: creates the folder driftwood-sandbox and the file app.log inside it.

    Make the folder, move into it and fill app.log with 2,000 lines. The log is the file Driftwood will rotate.

    macOS and Linux (bash, zsh)

    mkdir driftwood-sandbox && cd driftwood-sandbox
for i in $(seq 1 2000); do echo "2026-11-01T10:00:00Z INFO request $i ok"; done > app.log

    Windows (PowerShell 7)

    mkdir driftwood-sandbox; cd driftwood-sandbox
1..2000 | ForEach-Object { "2026-11-01T10:00:00Z INFO request $_ ok" } | Set-Content app.log

    Then list the folder.

    ls

    You should see: one file named app.log. On Windows the listing is a table with the same name.

    app.log

    If the shell says mkdir: cannot create directory, you are in a read-only folder. Run cd ~ and repeat this step.

  2. Create the config file

    Step 2 of 6 · Changes: creates driftwood.toml in the Sandbox.

    Run driftwood init. It writes a starter config in the current folder, and every later command reads it.

    driftwood init

    You should see:

    wrote ./driftwood.toml

    Print the file to see what it holds. The file uses TOML, a plain text format of key = value lines.

    cat driftwood.toml

    You should see: the five keys of the [rotate] table with their defaults. path = "." points at the current folder.

    [rotate]
path = "."
keep = 7
compress = "gzip"
max_size = "50MB"
schedule = "daily"

    If you see error: config not found in a later step, you left the Sandbox. Run cd driftwood-sandbox and repeat from here.

  3. Set the limits

    Step 3 of 6 · Changes: rewrites driftwood.toml in the Sandbox.

    Your log is 81KB, far below the default limit of 50MB, so nothing would rotate. Replace the config with a lower max_size (CFG4) and a smaller keep (CFG2). The other keys keep their defaults.

    macOS and Linux (bash, zsh)

    cat > driftwood.toml <<'EOF'
[rotate]
path = "."
keep = 3
compress = "gzip"
max_size = "64KB"
schedule = "daily"
EOF

    Windows (PowerShell 7)

    @'
[rotate]
path = "."
keep = 3
compress = "gzip"
max_size = "64KB"
schedule = "daily"
'@ | Set-Content driftwood.toml

    You should see: no output. The next step shows the new limits.

  4. Check before you run

    Step 4 of 6 · Changes: nothing. driftwood check only reads.

    Ask Driftwood what a run would do. driftwood check (CMD3) is safe to repeat as often as you like.

    driftwood check

    You should see: the config accepted and the log marked as due. The exit code is 1, which here only means a file is due.

    config: ./driftwood.toml ok
due  ./app.log   81KB > max_size 64KB
1 file due

    If the second line starts with ok instead of due, the log is not above max_size. Repeat step S1 and S3. If the first line is error: config not found, run pwd and make sure it ends in driftwood-sandbox.

  5. Run the rotation

    Step 5 of 6 · Changes: renames app.log to Generation 1, compresses it and creates a new empty app.log.

    Warning

    driftwood run rotates every Live log that is due in the folder named by path. Run it only in driftwood-sandbox. If you run it in a real log folder, its due Live logs are rotated too, and driftwood restore is how you get them back (see Restore a rotated file).

    Confirm where you are, then run it.

    pwd
driftwood run --verbose

    You should see: the path ends in driftwood-sandbox, then the report of one rotated file.

    rotated ./app.log -> app.log.1.gz
1 file rotated, 0 skipped

    List the folder again.

    ls

    You should see: three names. Sizes differ by a few bytes on your machine; the names matter. The hidden folder .driftwood also exists, and ls does not show it.

    app.log  app.log.1.gz  driftwood.toml

    The figure shows what changed. The new app.log is empty, and the 81KB of lines now sit in Generation 1.

  6. Restore the archive

    Step 6 of 6 · Changes: creates app.log.restored. Generation 1 and the Live log stay as they are.

    Rotation is reversible. driftwood restore (CMD4) copies a Generation back into a new file, so you can read the old lines. FILE is the Live log name, and Generation 1 is the default.

    driftwood restore app.log

    You should see:

    restored app.log.1.gz -> app.log.restored

    Print the first line to confirm the content came back.

    head -n 1 app.log.restored

    You should see: the first line you wrote in step S1. On PowerShell use Get-Content app.log.restored -TotalCount 1.

    2026-11-01T10:00:00Z INFO request 1 ok

    If you add --generation 9, the command prints error: generation 9 not found for app.log, because the Archive holds only Generation 1. Run ls and use a number from a file named app.log.N.gz.

What you learned

You wrote a driftwood.toml and set two of its options (S3). You asked Driftwood what a run would do before running it (S4), and you saw one Rotation turn an 81KB log into a compressed Generation and a fresh empty log (S5). You also undid it with a restore (S6). That is the whole cycle Driftwood repeats on a schedule.

Try it yourself

Add a second log and predict the result before you press Enter. Repeat the log command of step S1 with worker.log instead of app.log, then run driftwood check.

You should see: a line for each log. app.log is 0KB and is not due, and worker.log is 81KB and is due.

config: ./driftwood.toml ok
ok   ./app.log   0KB
due  ./worker.log   81KB > max_size 64KB
1 file due

Clean up

Warning

This deletes the folder driftwood-sandbox and everything inside it, including the Generation. It cannot be undone. Run it from the folder that contains the Sandbox, and use the folder name exactly.

macOS and Linux (bash, zsh)

cd .. && rm -r driftwood-sandbox

Windows (PowerShell 7)

cd ..; Remove-Item -Recurse driftwood-sandbox

You should see: no output, and ls no longer lists driftwood-sandbox.

Terms

Archive
The set of compressed Generations kept for one Live log.
Generation
A numbered Archive copy of a Live log, such as app.log.1.gz. Generation 1 is the newest.
Live log
A log file that an application still writes to, such as app.log.
Rotation
The act of renaming a Live log to Generation 1 and starting an empty Live log.
Sandbox
A throwaway folder where a tutorial runs, so no real file is touched.

How-to guide

Install Driftwood 2.4.0

Goal: driftwood --version prints driftwood 2.4.0. Done when it does, in a new terminal.

driftwood --version

Restore a rotated file

Goal: read the lines of a Generation without touching the Live log. Run driftwood restore FILE, where FILE is the Live log name, for example app.log. The result is FILE.restored.

driftwood restore FILE
