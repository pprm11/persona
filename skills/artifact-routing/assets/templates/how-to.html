Rotate Logs with Driftwood

In one minute

You will rotate and compress the logs of one application, so old logs shrink and only the last 7 stay on disk. You need Driftwood 2.4.0, write access to the log folder and about the size of the log folder in free disk. The steps cover Linux, macOS and Windows.

Step 5 renames the Live log, so step 1 makes a copy first. The Windows scheduled task in step 6 was not run yet; see the pending notice below.

Goal and done when

The goal is a log folder that Driftwood rotates by itself: each Rotation moves the Live log to a compressed Generation, and no more than 7 Generations stay.

Done when driftwood check prints 0 files due, and the log folder holds app.log plus Generations named app.log.1.gz and up.

This guide changes the log folder: it adds driftwood.toml, renames app.log and adds compressed Generations. It also adds one scheduled job.

Step 1 backs up the folder. If driftwood.toml does not exist, step 2 creates it and step 3 checks the keys. If it exists, go straight to step 4. Step 4 checks the config: ok leads to step 5, an error leads to the failure table. Step 5 rotates once, step 6 schedules it, and Verify ends the guide.

Steps

Run the steps in order. After each one, compare the output with the line that starts You should see. If it differs, stop and go to the failure table.

  1. Copy the log folder

    Make a copy now, because step 5 renames app.log.

    Linux and macOS

    cp -a /var/log/app /var/log/app.bak

    Windows (PowerShell)

    Copy-Item C:\logs\app C:\logs\app.bak -Recurse

    You should see: no output. ls /var/log/app.bak lists app.log.

  2. Create the config

    Driftwood reads driftwood.toml from the folder you run it in. Create it there.

    Linux and macOS

    cd /var/log/app
driftwood init

    Windows (PowerShell)

    Set-Location C:\logs\app
driftwood init

    You should see:

    wrote ./driftwood.toml

    If you see error: permission denied on /var/log/app, go to F2. If you see error: driftwood.toml already exists, keep your file and go to step 4.

  3. Check the keys

    Open driftwood.toml in your editor and make sure the [rotate] table holds these values, which are the defaults. A Rotation then keeps 7 Generations and compresses them with gzip. A Live log is due when app.log is above 50MB or once a day, whichever comes first. Leave path = "." as it is, because you run Driftwood from the log folder.

    [rotate]
path = "."
keep = 7
compress = "gzip"
max_size = "50MB"
schedule = "daily"

    You should see: the file saved, with these values. Step 4 checks them.

  4. Check the config

    Run this before the first rotation. It reads the file and changes nothing.

    driftwood check

    You should see:

    config: ./driftwood.toml ok
due  ./app.log   62MB > max_size 50MB
1 file due

    Exit code 1 here only means a file is due. If the first line differs, do not continue. error: config not found is F1. error: invalid value for keep is F3.

  5. Rotate once

    Changes your files

    This renames app.log to Generation 1 and starts a new app.log. Do it only if step 4 printed config: ./driftwood.toml ok. If nothing is due, the run changes nothing.

    driftwood run

    You should see:

    1 file rotated, 0 skipped

    If you see error: another run holds the lock, go to F4.

  6. Schedule it

    Driftwood does not start itself. Call driftwood run every hour. It rotates a Live log only when it is due, which means the size is above max_size or the schedule time has been reached, so an hourly call is safe.

    Linux and macOS (cron)

    crontab -l > crontab.bak
(crontab -l 2>/dev/null; echo '0 * * * * cd /var/log/app && driftwood run') | crontab -

    You should see: no output. crontab -l ends with the line 0 * * * * cd /var/log/app && driftwood run.

    Windows (PowerShell) [UNTESTED]

    schtasks /Create /SC HOURLY /TN Driftwood /TR "cmd /c cd /d C:\logs\app && driftwood run"

    You should see: SUCCESS: The scheduled task "Driftwood" has successfully been created.

Verify the result

Read the state instead of trusting the last output. Both checks must match.

Linux and macOS

driftwood check
ls /var/log/app

Windows (PowerShell)

driftwood check
Get-ChildItem C:\logs\app

You should see:

config: ./driftwood.toml ok
ok   ./app.log   0KB
0 files due
app.log  app.log.1.gz  driftwood.toml

The goal is met when 0 files due prints and at most 7 Generations are listed.

Run it again

Steps 3 and 4 are always safe to repeat. Steps 1, 5 and 6 are not, so read what a second run does before you repeat them.

StepSecond runResult
1. CopyHarmfulThe copy lands inside app.bak. Remove app.bak first, or use another name
2. CreateNo-opPrints error: driftwood.toml already exists and keeps your file
3. SetSafeSaving the same values changes nothing
4. CheckSafeReads only
5. RotateNo-op, then harmfulPrints 0 files rotated, 0 skipped while no Live log is due. When app.log is due again it rotates again and deletes the Generations beyond keep
6. ScheduleHarmfulA second line runs the job twice an hour. The Lock file stops the overlap, but remove the duplicate

Undo

Undo in reverse order. You can stop after any step.

  1. Remove the schedule

    Linux and macOS

    crontab crontab.bak

    Windows (PowerShell) [UNTESTED]

    schtasks /Delete /TN Driftwood /F

    You should see: no output on Linux and macOS. crontab -l no longer lists driftwood run.

  2. Restore a rotated file

    This writes Generation 1 to a new file and never overwrites app.log. Add --generation N for an older one.

    cd /var/log/app
driftwood restore app.log

    You should see:

    restored app.log.1.gz -> app.log.restored

    To go back to the state before step 5, copy the backup over the folder: cp -a /var/log/app.bak/. /var/log/app/ on Linux and macOS, or Copy-Item C:\logs\app.bak\* C:\logs\app -Recurse -Force on Windows.

  3. Remove the config

    rm /var/log/app/driftwood.toml

    You should see: no output. driftwood check now prints error: config not found (F1), which confirms the config is gone.

Glossary

Archive
The set of compressed Generations kept for one Live log.
Generation
A numbered Archive copy of a Live log, such as app.log.1.gz. Generation 1 is the newest.
Live log
A log file that an application still writes to, app.log in this guide.
Lock file
The file .driftwood/lock, which stops two runs from rotating at once.
Rotation
The act of renaming a Live log to Generation 1 and starting an empty Live log.
