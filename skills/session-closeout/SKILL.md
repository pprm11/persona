# Session Closeout

Use only on an explicit closeout or archive request, subject to applicable standing authorization. Review the entire objective and later steering, not only the last response. Inventory deliverables, pending decisions, running processes, attached worktree status and unpublished work, plus any follow-up or automation that still depends on the session.

## Learning

Identify durable, evidence-backed lessons that change future behavior. Check existing records; exclude secrets, duplicate rules, raw transcripts and temporary status. A successful command alone is not proof of practical improvement. Save only when authorized through [context-ingest](../context-ingest/SKILL.md) or the environment's permitted memory interface, then read back. State when a note still awaits consolidation.

## Eligibility and archive

Keep the session open when it owns unfinished work, a pending decision, a running operation, uncertain recovery, or an active follow-up whose continuation is not established. Verify a handoff’s destination and ownership before treating it as complete. Preserve worktrees and artifacts; do not kill processes, publish, or delete to make closeout possible.

When eligible and authorized, use the native archive operation for the intended session and verify the receipt or resulting state. If no tool exists or the result is uncertain, report that without claiming archive. Summarize saved learning, durable deliverables and the verified outcome.
