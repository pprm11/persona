# Context authority and change

## Admit relevant context

Read enough to frame the problem. Then identify the sources that actually govern the slice.
Distinguish inspected material, admitted authority and inputs used by a particular artifact/claim.
Reading a file does not automatically make every later output depend on it. A manifest records
observable admission and declared dependency; it does not reveal every latent model influence.

Prefer a small neighborhood: requirement, owner decision, affected contract, relevant code,
witnesses, constraints and dependencies. Add exploration when it resolves a specific uncertainty.
More connectors or a larger context dump can increase ambiguity rather than authority.

Capture material decisions in the current workflow: choice, reason, source, scope, version and
supersession. Link to deeper evidence instead of duplicating it. Preserve rejected/deferred
options and their revisit condition; later authors need to know why an attractive shortcut was
not used. Store decisions and concise justification, not private reasoning traces.

## Revalidate by material impact

| Change | Response |
|---|---|
| Inspected but unused exploratory source | Check whether the non-use assumption still holds; no global invalidation |
| Cosmetic edit to an admitted source | Assess materiality and retain the reason for reuse |
| Material change to an authoritative input | Revalidate dependent claims/artifacts and select their consumers |
| Policy/verifier/runtime/environment pertinent to the proof | Invalidate the affected evidence identity; compare versions before reuse |
| Dependency or materiality unknown | Broaden bounded verification conservatively; mark the unresolved boundary |
| Conflicting authority | Expose the conflict and route the material decision to the proper owner |

Rewriting impacted generated output can be correct when the source invalidates its basis.
Patching can also be correct when it preserves a valid derivation. Choose by the affected
contract and proof; never silently discard useful human edits or regenerate the entire repo.

The change record should answer what became stale, why, which current proof replaces it and
what remains unresolved. Old receipts remain historical records; do not relabel them as evidence
for a new target, source or version.
