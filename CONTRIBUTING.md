# Contributing and releasing skills

Add or rename a skill under `skills/<name>/SKILL.md` with supported frontmatter and a clear ownership boundary. Preserve useful existing behavior, make optional sibling dependencies usable alone, and avoid private data and unlicensed vendor material. Update the catalog and links together.

Before release, run `python -I -X utf8 -m unittest discover -s tests` and `python -I -X utf8 -m unittest discover -s skills/artifact-routing/tests`. For the release gate set `PERSONA_PRIVATE_PATTERNS_FILE` to an external UTF-8 JSON file containing a nonempty array of private regex patterns, then run `python -I -X utf8 tests/catalog_audit.py`. The gate scans all tracked and unignored candidate text files with generic patterns and the private patterns, and fails closed if the file is missing or empty. Keep the private file outside this repository. Automated checks cannot establish semantic privacy or license provenance. Also run including each skill's tests, the repository quality gate and the skill creator validator if available. Inspect changed content and resources for privacy, English, source attribution, valid links and behavioral routing. Document untested dependencies and limitations. Personal repository release does not depend on CI; the local suite must pass.

Release only within the user's current authorization and scope. Review the exact commit and publish it to the intended GitHub repository. After publication, perform one genuine isolated smoke install from the published remote using the normal `npx skills add` CLI, verify the installed skill and clean up the isolated test directory. Do not fake telemetry, repeatedly install to influence indexing, or claim a local install proves a remote release.

Check the public skills.sh listing separately. Record the exact published commit, CLI invocation and outcome, and listing observation. A published and successfully installed skill can remain not yet indexed; report that state honestly and recheck later when appropriate. The [skills.sh FAQ](https://www.skills.sh/docs/faq) describes discovery via normal install activity, not a separate publication API.
